# Изменения проекта Saukele (Спринт: Финальная защита)

В рамках подготовки к финальной защите были выполнены следующие задачи:

## 1. Frontend демо приложение (React + Vite)
- Инициализирован проект на React 18, Vite, TypeScript и TailwindCSS.
- Настроен роутинг (React Router v6) для публичных и защищенных страниц.
- Настроен глобальный контекст `AuthContext` для управления состоянием пользователя.
- Реализованы публичные страницы:
  - `/login` (вход)
  - `/register` (регистрация)
  - `/verify-email` (верификация)
  - `/forgot-password` и `/reset-password` (восстановление пароля)
- Реализованы ролевые дашборды:
  - **HOST dashboard:** Управление реестрами, подарками (с CRUD и отслеживанием прогресса сбора средств), управление гостями (построение визуального семейного дерева по `parent_id` и `tier_rank`).
  - **GUEST dashboard:** Просмотр доступных реестров/подарков, форма внесения вклада с мультивалютностью и историей вкладов.
  - **VENDOR dashboard:** Отслеживание статуса `FUNDED` подарков, подтверждение покупки (`PURCHASED`).
  - **COURIER dashboard:** Отслеживание статуса `PURCHASED`, подтверждение доставки (`DELIVERED`).
  - **ADMIN dashboard:** Просмотр всех пользователей, управление их статусом (блокировка/разблокировка), мониторинг очереди email-сообщений (BullMQ), а также создание новых администраторов.
- Настроен `axios` инстанс с автоматическим прикреплением токена и обновлением (refresh) при ошибке 401.

## 2. Admin Registration Endpoint (Backend)
- Добавлен защищенный эндпоинт `POST /api/v1/admin/register-admin`.
- Эндпоинт проверяет наличие секретного ключа из переменной окружения `ADMIN_REGISTRATION_KEY` в заголовке `X-Admin-Key`.
- Создает пользователя с ролью `ADMIN` с автоматическим подтверждением email (`isEmailVerified = true`).
- Интегрирован UI интерфейс на стороне фронтенда (в ADMIN dashboard) для вызова данного эндпоинта.

## 3. Docker Compose и Контейнеризация
- Создан корневой `Dockerfile` для backend-части с многоступенчатой сборкой (Node.js 20 Alpine).
- Создан `Dockerfile` в папке `/frontend` для сборки React-приложения и раздачи статики через `nginx`.
- Написан `docker-compose.yml` со следующими сервисами:
  - `postgres` (PostgreSQL 15 с `healthcheck`)
  - `redis` (Redis 7 с `healthcheck` для BullMQ)
  - `backend` (Express API на порту 3000, автоматически применяет миграции при старте `npx prisma migrate deploy`)
  - `frontend` (Nginx на порту 5173, проксирующий статику).
- Все сервисы связаны между собой и работают в единой сети Docker.

## 4. Файлы развертывания (Deployment)
- Создан `DEPLOYED_URL.txt` — шаблон для сохранения ссылок после деплоя.
- Обновлен файл `CHECKLIST.txt` — добавлены галочки для всех выполненных задач по Frontend, Docker и Deployment.
- Обновлен `README.md` — добавлен подробный раздел `Deployment`, содержащий инструкции для локального запуска через `docker-compose` и для облачного хостинга (Render.com / Railway.app).

## Дополнительно
- Все исходные требования по запрету использования raw SQL (только Prisma ORM), сохранению исходной структуры БД и невмешательству в основной код бэкенда (кроме добавления admin эндпоинта) были строго соблюдены.
